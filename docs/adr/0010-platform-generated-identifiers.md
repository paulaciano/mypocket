# ADR-0010: Platform-generated identifiers instead of personal data

- **Status:** Accepted
- **Date:** 2026-11-20

## Context

A sender needs a way to say who receives a transfer, and history, events and responses need to refer
to the other party. Using personal data for this (email, phone, name, national id) spreads it across
tables, events, logs and other customers' screens, which widens the impact of any leak and the
obligations to protect it.

## Decision

- Personal data (email and password hash) lives **only in the user module** and is used only for
  login (P1).
- Everywhere else people and wallets are referred to by **identifiers generated by the platform**
  (P2): internal UUIDs for users and wallets, and a public **account number** per customer wallet.
- The account number is the identifier a customer shares to receive money (T1). It has 10 digits,
  the last one a Luhn check digit that catches typing mistakes; it is generated randomly, is unique,
  and is never reused, even after the wallet is closed (W2, W9).
- One account number per wallet, rather than per user: it already identifies the currency, so the
  sender does not need to choose it.
- The JWT subject is the user id (S18).

## Alternatives considered

- **Email or phone as the recipient identifier:** familiar to users, but makes personal data part of
  every transfer, event and history line.
- **User-chosen username/alias:** memorable, but people often choose names that reveal their identity,
  and it needs reservation, profanity and change rules.
- **Exposing the wallet UUID:** generic, but too long to type or dictate and without typo detection.

## Consequences

- Personal data stays in one table and the events can be consumed by any service (including fraud
  detection) without handling personal data.
- Customers must share an account number instead of an email. A service that resolves personal data
  to an account number can be added in front without changing the core.
- Account number generation needs a uniqueness check; a collision is retried with a new random number.
